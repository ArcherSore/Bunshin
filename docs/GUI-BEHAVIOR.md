# Bunshin GUI 行为说明

Windows x64 / .NET 10 WPF 程序。需要管理员权限和交互式桌面；manifest 为 asInvoker，由程序在启动时自行请求提权（`--help` 在提权前输出）。

## 运行时文件

- 任务配置：`<程序目录>\config\configurations.json`
- 滚动日志：`<程序目录>\logs\Bunshin-yyyyMMdd[.序号].log`
- Worker 启动失败日志：`<程序目录>\logs\Worker.bootstrap.log`，只在 Worker 启动失败或异常退出时写入
- 框架日志与图片：`<程序目录>\debug`，失败截图位于 `on_error`，识别可视化图片位于 `vision`
- 诊断包：`<程序目录>\debug\exports`，每卷约 24.5 MB，保留最近 10 次导出
- 框架偏好：`<程序目录>\config\maa-{save-on-error,debug-mode}.txt`

设置页提供三个独立开关：SaveOnError 默认开启，SaveDraw 和 DebugMode 默认关闭。SaveDraw 不保存，程序重启后恢复关闭。
更改后从下一次识别开始生效，无需结束桌面分身；GUI 在切换开关和 Worker 连接时同步当前选择。
框架日志和图片没有容量上限，由 MaaFramework 在设置 LogDir 时删除 7 天前的文件；设置页可手动清理。

项目根目录固定为应用程序目录，`interface.json` 直接从 `Bunshin.exe` 同级目录读取。日志按天和 10 MiB 滚动，保留 14 个文件，可从主窗口直接打开当前日志目录。若程序目录不可写，日志会回退到 LocalAppData 或临时目录并记录 WARN。

游戏可在分身中手动启动，也可由当前任务配置选中的 Project Interface pretask 启动。GUI 不固定游戏启动器路径或参数；启动、登录等游戏行为由 MaaNOP 项目声明的程序和资源实现。

## 操作语义

- 首页“准备运行环境”、运行控制栏的“观看分身”会确保 RDP ActiveX 已连接。
- 隐藏子桌面或点击其 X 不会断开 RDP。
- Worker 与任务配置就绪后，无论子桌面当前显示或隐藏，均可从主窗口开始任务。
- “准备运行环境”只创建或恢复 Session、连接 RDP 并启动或恢复 Worker；准备完成后仍由用户点击“开始任务”。
- 启动 Worker 前确认目标 Child Session 中没有同名 Worker，连接后再核验进程和 Session 身份。
- 主窗口 X 默认隐藏到托盘；关闭该设置后进入安全退出流程。
- “结束桌面分身”和退出程序会注销 Child Session；退出前会确认。

## 任务启动与结果提醒

| 结论 | 用户看到的结果 |
| --- | --- |
| 已接纳 | Worker 已登记本次任务。GUI 继续跟踪运行进度和终态，接纳本身没有额外提醒。成功时显示完成结果，失败时显示失败任务（如已知），取消时静默结束。 |
| 未能启动 | 准备失败、已确定请求正文未发出，或所有可能发出的提交都已被明确拒绝或查明未登记。界面给出失败阶段和原因。 |
| 启动结果未知 | 请求正文可能已经发出，Worker 已确认退出，仍缺少接纳或排除这次提交的证据。任务可能已经开始执行。 |
| 运行结果未确认 | Worker 已接纳任务，但在它退出或后续任务覆盖旧快照后，仍无法确认原任务的终态。 |

应答超时或暂时断线时，GUI 保留待确认状态，通过原 Worker 的快照继续确认。同一 Worker 上的同一 Run 最多主动提醒一次，重复快照和重连不会重复通知。已观察到的运行中任务进入 Faulted 时，GUI 可提醒任务可能仍在运行，并提供结束桌面分身的恢复入口。定时任务成功后的分身收尾若失败，会另报收尾结果。

用户点击“准备并开始”后，如果准备运行环境失败，主窗口可见且未最小化时显示窗内错误框。主窗口隐藏或最小化时通过托盘提示。
手动启动提交后，GUI 按主窗口状态呈现需要报错的启动结论。窗口可见且未最小化时显示窗内错误框，保留原操作、异常原因及适用的 Windows Hello 登录指引。窗口隐藏或最小化时通过托盘提示。运行终态和无人值守任务的提醒在主窗口处于前台时抑制气泡，窗口退到后台时使用托盘。用户显式重试后仍可看到该次操作的前台错误。

退出确认或更新交接期间，GUI 暂存待交付的提醒、定时完成与收尾、自动退出请求。取消退出或更新交接失败后恢复交付，尚未交付的提醒按原 Run 补发一次。确认退出或更新成功接管后，丢弃待交付项。

如果 `-q` 已经请求退出，但结束运行环境未确认（例如注销分身失败），GUI 取消这次退出并保留窗口，不再为原 Run 重试退出。在用户成功结束桌面分身之前，“运行环境状态未知”会挡住开始和定时；结束成功后窗口保持打开，定时照常恢复。

## 运行结果与继续运行

运行面板的运行结果分区在运行中总是显示。结束后，只要记录中的任务序列等于当前配置已勾选任务序列的末尾一段（含完全一致），就继续显示“上次运行”；增删、排序、取消勾选或切换配置后对不上时隐藏。故障恢复状态下隐藏。记录不持久化，启动新 Worker 时清空。已知边界：在计划最前面新增任务后记录不隐藏；两个配置结尾任务相同时，记录可能出现在另一个配置下。

记录结束且有未成功（失败、停止或未执行）的项，且其中第一个不是当前计划的第一项时，分区右上角显示“继续运行”。点击后另起一次 Run：用当前配置的参数，从该项执行到计划末尾，该项从头执行，之前的任务和前置程序不再执行。可用条件、阻止原因和启动流程与“运行”相同，需要时先准备运行环境；桌面分身已关闭但记录还在时也可以点。新记录只含本次执行的项，再次失败可以再继续。

没有开始的任务计划（例如 Worker 明确拒绝）只由下一次相同输入的“运行”复用；“继续运行”不复用任何此前的计划，“运行”也不复用“继续运行”的计划。“继续运行”途中准备运行环境失败后，“重试准备运行环境”和“运行”执行完整计划。

## 项目预设

项目可在 `interface.json` 的 `preset` 数组声明预设。在配置标签条点击“从预设新建配置”，
选择后会新建并激活一份普通配置；可继续编辑、重命名或删除，不覆盖已有配置，也不自动同步后续预设变化。
未声明预设时隐藏此入口，原有“新建空配置”保持可用。

支持任务顺序、`enabled`（默认 true）、select/switch 的 case.name、checkbox 的 case.name 数组、input 字段值和嵌套选项。
`enabled: false` 的任务或前置任务不加入配置，其选项也被忽略；未指定的选项跟随项目默认值。
支持 `preset.pretask`：只选择其中启用且适用的前置任务，跳过不适用项，并仍按顶层 pretask 顺序执行；
省略或为空数组时不选择前置任务。新配置只使用项目默认值和预设内容，不继承当前配置的任务、前置任务或参数。

沿用现有配置的共享选项模型：不同任务对同名选项指定的值必须一致，input 的不同字段可合并；
发生冲突时拒绝创建，不覆盖原配置。未知任务或前置任务、非法选项值及重复任务也会拒绝。
本功能不扩展现有 Project Interface 支持范围：`import`、hotkey、国际化和图标渲染仍未支持，
展示字符串沿用现有任务的处理方式。

## 项目资料

设置 → 关于顶部按 MXU 显示项目 `label`（未声明时为 `name`）和 `icon`，没有可用图标时显示应用图标；
下方展示同一次 Project Interface 加载中的顶层 `description`、`contact`、`github` 和 `license`。
简介、联系方式和许可证按 welcome 的规则识别内联 Markdown 与项目目录内的文件（包括 `LICENSE`），
另外保留 HTTP(S) 链接，只在点击时打开浏览器，不自动下载正文。明确的文件引用读取失败时只在对应位置提示。
仓库地址沿用 Update Engine 的 GitHub 仓库校验规则；许可证正文通过“查看许可证”在欢迎信息同款弹窗中阅读。
缺失或空白的资料隐藏，重新加载项目时刷新。

主窗口标题栏和任务栏使用顶层 `title`，未声明时按协议为 `name version`（不取 `label`）。
`icon` 是相对项目目录的图片路径，用于窗口、标题栏、托盘和关于页，托盘提示显示项目 `name`；
未声明、越界或无法加载时使用 Bunshin 默认图标。`$` 开头的翻译键按键名显示，重新加载项目时刷新。

## 前置任务

在“添加任务”中添加前置任务和普通任务。前置任务集中显示在列表顶部，两类任务均可在各自组内拖动，并共用勾选、参数编辑和移除操作。
取消勾选会保留任务和参数，重新打开后仍保持原勾选状态。开始时只检查本次要执行的任务和它们使用的参数。
前置任务按 Project Interface 声明顺序先执行。只勾选前置任务时也可开始，Worker 不创建 MaaFramework Controller。

前置程序在 Child Session 中运行，工作目录为 `interface.json` 所在目录。固定参数之后按需追加一个紧凑 JSON 参数，内容为该 pretask 引用的选项值；这些选项不合并到普通任务的 Pipeline Override。

启动失败、非零退出或每项 180 秒超时会停止后续任务。停止或超时后最多等待 30 秒确认清理；退出未确认时保留 Active Run，界面只允许通过结束桌面分身恢复。成功完成的前置任务保留其启动的游戏。

## Known Issue

首次 Child Session 偶尔出现 `CrossDeviceResume.exe` 的 Windows 系统弹窗，目前不影响功能。本项目不修改 SystemApps、ACL 或系统文件来处理该弹窗。
