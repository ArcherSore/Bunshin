# 领域文档

本仓库采用单上下文布局：根目录 [GLOSSARY.md](../../GLOSSARY.md) 是项目术语表，[docs/adr/](../adr/) 保存架构决策和产品取舍。

开始相关工作时读取术语表和涉及区域的 ADR，使用其中的推荐术语。若代码与术语或 ADR 冲突，先核对当前事实，再决定是否修正文档或提出新的设计选择。做产品或交互取舍前，先查 docs/adr/ 有没有现成的决定，再决定是否问用户。

只在术语实际形成或改变时更新 GLOSSARY.md；用一两句话定义概念，不写实现、流程或历史。

决策同时满足三条时新增 ADR：以后的会话会再问、或会再提议被否决的方案；未来读者会觉得意外；确有合理替代方案。用户否决某个方案、而且理由以后还用得上时，主动提议记成 ADR。
ADR 用一到三句写背景、决定和理由；被否决的方案值得记时加「考虑过的方案」；最后用「依据」写明参考了哪个产品的哪种做法，以及是调研得出还是用户直接拍板。决策改变时在原文末尾追加带日期的「更新」小节，不另开文件。文件按需创建，不为一次讨论或已完成任务补文档。

docs/ARCHITECTURE.md 只描述当前系统的组件、边界、主要流转和不变量；稳定协议才保留独立 reference。
实现过程、测试输出、验收流水账、调研报告和讨论纪要不进长期文档，由 Git history 和 Issue/PR 承担；调研得出的决定写进 ADR。
不建归档目录保存过时内容；完成工作后清理失效链接与过期说明。
