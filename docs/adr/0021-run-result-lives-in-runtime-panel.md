# 运行结果集中在运行面板，可从未成功项继续运行

原先的运行摘要卡片说不清结果，运行结束后也看不到每一项的状态。进度和结果改为只在运行面板的无卡片分区里呈现，执行计划任务行不再显示状态；失败或停止后可“继续运行”，即用当前配置另起一次 Run，从第一个未成功项执行到末尾，不重跑此前的任务和前置程序，也不与上一次的记录合并或持久化。这样看到哪几项就执行哪几项，不需要新增运行状态；代价是游戏已卡死或关闭时只能完整重跑，收起运行面板时看不到进度和结果。

## 考虑过的方案

- **结果标在执行计划任务行上**：与面板分区重复同一批状态。
- **继续前重跑前置程序，或合并历次结果**：前者让实际执行范围超出用户看到的剩余项，后者要求 GUI 另存历次状态。
- **面板里保留“重新运行”**：执行计划的“运行”已经是完整重跑。
- **显示失败原因行**：普通任务拿不到可读原因，用最后一条日志代替会和运行动态重复。
- **应用内查看失败截图**：按任务起止时间可以准确找到本次的图，但记录还在时游戏画面多半仍停在原处，暂不值得为此做浮层。

## 依据

用户通过可切换原型比较后拍板，分区样式参照 Claude 桌面端侧栏。

## 更新（2026-11-28）：运行记录归属任务配置并持久化

按任务序列匹配当前计划，会让改顺序或勾选后记录消失，也会让它出现在结尾任务相同的另一份配置下。改为每份任务配置按 ID 保留最近一次运行记录并持久化，修改配置内容不影响它；只保存已结束的结果，且不含任务参数（可能含密码）。“继续运行”改为按当前计划顺序，从第一个仍勾选且记录中未成功的项执行到末尾，起点是计划第一项时也提供，没有这样的项时隐藏，悬停只提示起点。本节取代正文中的“不持久化”和“看到哪几项就执行哪几项”：执行范围可能与记录列出的项不同；仍不合并历次记录。

### 考虑过的方案

- **计划改动后置灰“继续运行”**：保住范围一致，但无法取消勾选总是失败的项后继续。
- **固定从原失败项开始**：挪到它前面的未成功项会被漏掉。
- **只执行记录中未成功的项**：执行内容跳跃，与“从某项执行到末尾”不一致。
- **边运行边保存，未看到结束的标为“未确认”**：要多一种状态和对应规则；代价是运行中退出时该次没有记录。
- **保留多次记录并提供历史页**：过程细节已在日志中，历史页是另一项功能。

### 依据

用户直接拍板。调研中 MXU、MFAAvalonia 把运行状态挂在实例的任务行上，调整顺序时状态跟随；March7thAssistant、BetterGI 将运行记录写入磁盘。
